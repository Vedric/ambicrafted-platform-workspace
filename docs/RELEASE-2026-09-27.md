  **Investigation**, **Voice**, **Knowledge** and **Telemetry**. Component details

## AURA and tools

AURA is a local AI assistant with English and French female synthetic voices.
The conversation language is independent of interface language. Manual recording
creates an editable draft. Explicit hands-free mode sends after a speech pause,
reads the reply and resumes listening. Recording closes during inference/playback;
`Speak now` interrupts playback before recording. Escape, end conversation,
navigation, a hidden tab or an error stop the loop. Bounds are 12 seconds of initial
silence, 90 seconds / 8 MiB per recording and 20 exchanges per conversation.

The instrument follows measured microphone energy or the native audio element's
actual WAV playback position. Unsupported visualization never blocks playback.
Decorative pause/reduced motion works independently of speech processing. Turning
off automatic reading during a request cancels pending automatic speech.

AURA does not call tools, approve investigations or execute remediation. The
supervised SRE workflow supplies sourced proposals with human review. The local
MCP configuration supplies two verified servers: four runbook tools and nine
read-only control tools. A Neo4j service or unrestricted shell/filesystem adapter
has not been added without a concrete data/use requirement. Existing SQLite and
Qdrant serve the implemented state and semantic-search needs.

## Follow-up provenance correction

The final maintenance review found that the UI's direct semantic search could
return a pre-edit indexed passage even though the MCP already rejected a stale
corpus. The API now validates current corpus and passage provenance, applies the
same minimum relevance threshold and refuses changes during the query. Missing
or inconsistent provenance produces the existing sanitized unavailable response;
literal search and explicit reindexing remain available. Contract tests compare
canonical segmentation against the real indexer. This does not weaken the agent's
citation guard or automatically republish source changes. See
[ADR0019](adr/0019-provenance-recherche-console.md).

## Deployment decision and remaining work

**Conditional GO:** supervised local use on the qualified workstation, with reviewed
sources, private state, backups and explicit operator decisions.

**NO-GO:** unqualified external production, remote multi-user access, or shared-client
hosting. The 2026-09-26 promoted image assessment still records **0 CRITICAL / 166
HIGH package occurrences**; this application release does not change those images.
No scanner suppression or broad waiver was introduced. Before production:

1. Remediate remaining image findings or produce specific, justified reachability
   assessments for the exact artifacts; rescan and obtain security acceptance.
2. Qualify the target environment, backup/recovery objectives and operational SLOs.
   Source runbooks require their own private backup in addition to indexed snapshots.
3. Obtain client-specific evaluation and acceptance with reviewed representative
   examples; synthetic tests do not prove model correctness on arbitrary incidents.
4. Use a dedicated VM per client today. Remote/shared access requires a separately
   designed identity, authorization and tenant-isolation boundary, TLS and operations.
5. Test physical audio hardware and browsers used by the operator. This delivery
   automates Chromium desktop/mobile, not Safari, Firefox or every mobile device.
